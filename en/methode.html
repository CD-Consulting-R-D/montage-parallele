Method

The cycle: mandate, gates, execution, audit, record

All work follows the same cycle. The Supervisor drafts a mandate: the object, the deliverables, what is forbidden, and the points where the session must stop. The human reads it and lodges it; the session opens by checking that the calibre actually running is the one intended. At each stop, it waits for a gate: an explicit formula, spoken by the human and addressed to the window that will carry it out — “go push … — window …”. Nothing is published without a gate. Execution proceeds in batches, each one measured before and after. Another session then audits the work on the evidence, replaying the checks. Finally, the Supervisor records it: in the version history, each decision carries a mark that shows who took it and when.

The registers

The squad works on versioned registers: the task tracker, the dated chronology of decisions, the inventory of risks and their safeguards, the collaboration charter, the lexicon. They are working documents: they are corrected by erratum, never rewritten. Every time that goes into them is read from the clock, never estimated.

Rules a machine can check

A rule that depends on a model's judgement does not survive a change of model. A rule that a script can check — a formula, a prefix, a count — holds. So every new rule must pass a test: which check would say it has been broken? And every new doctrine must answer another question: which existing arrangements does it make wrong?

An example: how a knowledge-base entry is made

An entry starts as Markdown, with its numbered sources. A generator publishes it by subtraction: the working header is removed, the body stays as it is. It writes the entry's line in the chapter's register, then rebuilds the chapter index and the site's home page from that register. Going online waits for its gate. Every claim points to a public source the reader can open again, and the list of sources closes the entry. The same generator serves all six chapters: a template fix is made once.
